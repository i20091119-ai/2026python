## 슬라이드 Z — rr.py · 원의 넓이 (정상 동작)

```python
pi = 3.141592
r = int(input("반지름을 입력해 주세요"))

s = pi * (r ** 2)
print("넓이는 = ", s)
```

Variables 패널: `pi = 3.141592`, `r = 10`, `s = 314.1592`

Shell
```
>>> %Run rr.py
 반지름을 입력해 주세요10
 넓이는 =  314.1592
```

> 메모
> - 여기서는 원주율을 `3.141592` (소수점 6자리)로 쓴다.
>   앞의 교재 슬라이드는 `3.14159265` 였다. 문제로 낼 때 어느 쪽을 쓸지 통일할 것.
> - 제곱 연산자 `r ** 2` 를 처음으로 실제 코드에서 쓴다.
> - 두 엔진 모두 `314.1592` 로 같다. 확인 완료.
> - `print("넓이는 = ", s)` 처럼 쉼표를 쓰면 `= ` 뒤에 공백이 하나 더 붙어
>   `넓이는 =  314.1592` (공백 2칸)로 나온다. 출력 형식 문제로 쓸 때 주의.

## 슬라이드 AA — sss.py · 헤론의 공식 (버그 있음)

```python
a=int(input("a의 길이는"))
b=int(input("b의 길이는"))
c=int(input("c의 길이는"))

s= (a+b+c) / 2

aa = (s*(s-a)*(s-b)*(s-c))**1/2

print("넓이는 ", aa)
```

Variables 패널: `a = 10`, `aa = 0.0`, `b = 30`, `c = 40`, `s = 40.0`

Shell
```
a의 길이는10
b의 길이는30
c의 길이는40
넓이는  0.0
```

손글씨 판서: `√4 = 4^(1/2)`

### 여기에 버그가 두 겹으로 있다 (아주 좋은 소재)

**1) 연산자 우선순위 버그**

`**` 가 `/` 보다 우선순위가 높다. 그래서
```python
(s*(s-a)*(s-b)*(s-c))**1/2
```
는 `( ... )**1` 을 먼저 계산한 뒤 `2` 로 나눈다. 즉 **제곱근이 아니라 그냥 반으로 나눈 것**이다.

판서하신 `√4 = 4^(1/2)` 대로 하려면 괄호가 필요하다.
```python
aa = (s*(s-a)*(s-b)*(s-c)) ** (1/2)
```

**2) 하필 그 버그가 안 보이는 입력을 넣었다**

`a=10, b=30, c=40` 은 `10 + 30 = 40` 이라 삼각형이 될 수 없는 **퇴화삼각형**이다.
- `s = 40.0`, `s-c = 0` → 곱이 `0`
- `0 ** 1 / 2 = 0.0`, 올바른 식으로 해도 `0 ** 0.5 = 0.0`
- **두 결과가 우연히 똑같아서 버그가 드러나지 않았다.**

두 엔진에서 실제로 돌려 확인한 값

| a, b, c | 버그 있는 식 | 올바른 식 |
|---|---|---|
| 10, 30, 40 | 0.0 | 0.0 |
| 3, 4, 5 | 18.0 | 6.0 |
| 6, 8, 10 | 288.0 | 24.0 |
| 5, 5, 6 | 72.0 | 12.0 |

CPython 과 브라우저 엔진 결과가 완전히 같다.

## 적용 시 만들 예제 후보 (배치 6)

- **연산자 우선순위 함정** : `x ** 1/2` 와 `x ** (1/2)` 의 차이 (결과 예측)
- 헤론의 공식 제대로 완성하기 (3, 4, 5 를 넣으면 6 이 나와야 함)
- 왜 10, 30, 40 에서는 버그가 안 보였는지 설명하는 해설
  (테스트 값을 잘 고르는 것의 중요성 — 여러 입력으로 채점하는 이 앱의 취지와도 맞음)
- 원의 넓이 계산기 (`r ** 2` 사용)
- `print("넓이는 = ", s)` 의 공백 2칸 문제
