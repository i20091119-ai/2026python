## 화면 1 — if / else 기본 + 순서도

```python
a = 10

if a > 0 :
    print("0보다 큽니다")
else :
    print("0보다 작습니다")
```

Variables: `a = -1` (여러 번 값을 바꿔 가며 실행하신 흔적)

Shell
```
NameError: name 'printl' is not defined     ← 그 전 실행에서 난 오타 오류
>>> %Run 104.py
0보다 큽니다
>>> %Run 104.py
>>> %Run 104.py
0보다 작습니다
```

빨간 펜: **순서도**를 그려 설명하심
`a = 10` (사각형) → `a > 0` (마름모) → Yes → 출력 (사각형)

> **두 가지 소재**
> 1. `printl` 오타로 난 `NameError`. 이전 화면의 `Print(b)` 대문자 오류와 같은 계열.
> 2. **이 코드의 논리 구멍**: `a = 0` 일 때 "0보다 작습니다" 가 출력된다.
>    0 은 크지도 작지도 않은데 else 로 떨어지기 때문이다.
>    `elif a == 0` 을 넣어야 한다는 것을 끌어내기 아주 좋은 예.

> 아주 좋은 예다. 문제로 만들 만하다.
> (출력 문구도 아직 앞 예제 것을 그대로 두신 상태)

## 화면 3 — 세 수 중 가장 큰 수 (중첩 if, 미완성)

```python
a = int( input("첫번째숫자를 입력해주세요") )
b = int( input("두번째숫자를 입력해주세요") )
c = int( input("세번째숫자를 입력해주세요") )

if a > b :
    if a > c :
        print("a가 제일 큽니다")
    else
        print("c가 제일 큽니다")
else :
    if b > c :
        print("b가 제일 큽니다")

    print("못함")
```

빨간 펜: `3개다`, `숫자중에`, `가장 큰 수`, `a b c` 각각 동그라미,
`if (a > b)` / `else` / `if (b) > (c)` / `p("b")` / `p("c")` 구조도

Shell
```
>>> %Run 104.py
총점을 입력해주세요45
보통
>>> %Run 104.py
총점을 입력해주세요100
매우잘함
```

> **문제점 두 개**
> 1. 10행 `else` 에 **콜론이 없다** → SyntaxError
> 2. 안쪽 `if b > c` 에 대응하는 `else` 가 없다.
>    그래서 **c 가 가장 클 때(a<=b 이고 b<=c) 아무것도 출력되지 않는다.**
>    실제로 확인함: `a=1, b=2, c=3` 을 넣으면 출력이 없다.
>    (반례를 2000번 무작위로 돌려 여러 개 확인했다)
> 3. 마지막 `print("못함")` 은 들여쓰기 위치상 else 블록 안에서 항상 실행된다.

## 화면 4 — 네 수 중 가장 큰 수 (토너먼트 방식, 정상 동작)

```python
a = int( input("첫번째숫자를 입력해주세요") )
b = int( input("두번째숫자를 입력해주세요") )
c = int( input("세번째숫자를 입력해주세요") )
d = int( input("네번째숫자를 입력해주세요") )

if a > b :
    max1 = a
else :
    max1 = b

if c > d :
    max2 = c
else :
    max2 = d

if max1 > max2 :
    print("가장 큰 숫자는 ", max1)
else :
    print("가장 큰 숫자는 ", max2)
```

Variables: `a = 10`, `b = 20`, `c = 30`

빨간 펜: `max1` 상자를 그리고 `a`, `b` 를 묶고, 옆에 `c`, `d` 를 묶는 그림

Shell
```
세번째숫자를 입력해주세요5
b가 제일 큽니다
>>> %Run 104.py
첫번째숫자를 입력해주세요10
두번째숫자를 입력해주세요20
세번째숫자를 입력해주세요30
c가 제일 큽니다.
```

> **좋은 방법**: 둘씩 짝지어 이긴 것끼리 다시 비교하는 **토너먼트 방식**.
> 중첩 if 로 모든 경우를 따지는 것보다 훨씬 간단하고 실수가 적다.
> 확인함: 무작위 2000 조합에서 항상 정확한 최대값을 낸다. 반례 없음.
> 화면 3의 중첩 방식과 대비시키면 아주 좋은 교육 자료가 된다.

## 화면 5 — 논리 연산자 or

```python
#max1 = 0
#max2 = 0

a = int( input("국어 점수를 입력해주세요") )
b = int( input("영어 점수를 입력해주세요") )
#c = int( input("세번째숫자를 입력해주세요") )
#d = int( input("네번째숫자를 입력해주세요") )

if (a >= 80) or (b >= 80) :
    print("잘했어요")
else :
    print("분발하세요")
```

Variables: `a = 40`, `b = 100`

빨간 펜: `같지않다`, `not`, 그리고 크게 동그라미 친 `not (a == 80)`

> `or` 는 **둘 중 하나만 참이어도** 참. 국어 40점이어도 영어 100점이면 "잘했어요".
> `not (a == 80)` 은 `a != 80` 과 같다는 것을 판서로 설명하심.
> 조건에 괄호를 씌워 읽기 쉽게 하신 것도 좋은 습관.

## 적용 시 만들 예제 후보 (5주차)

- `if a > 0 / else` 만 있을 때 `a = 0` 이 잘못 분류되는 문제 → `elif` 로 고치기
- 주석 처리한 변수를 조건에서 쓰면 **입력값에 따라** NameError 가 나는 경우
- 세 수 중 최대: 교수님의 중첩 if 를 완성하기 (빠진 else 채우기)
- 네 수 중 최대: 토너먼트 방식 그대로 구현 (여러 입력으로 채점)
- 중첩 if 방식과 토너먼트 방식 비교 (어느 쪽이 실수가 적은가)
- `or` 와 `and` 구분: 국어 또는 영어가 80 이상 / 둘 다 80 이상
- `not (a == 80)` 과 `a != 80` 이 같다는 것 (객관식)
- `else` 뒤 콜론 빠뜨렸을 때 나는 SyntaxError 고치기
- 성적 등급 프로그램 완성 (평균으로 매우잘함/잘함/보통/못함)
